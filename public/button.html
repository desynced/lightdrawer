Add a “Stamp this with LightDrawer” button

Let people on your website timestamp a file — without uploading it, creating an account, or loading extra trackers.

The file never leaves the visitor’s device. LightDrawer is free. There are no analytics scripts in these snippets, and visitors finish the stamp on this site with the usual human check.

The simple link (no JavaScript)

This is the version most sites should use. It is a normal link. When someone clicks it, they come here, drop the file themselves, and get a receipt. You can style it however you like.

Warn if they drop the wrong file

If you already know the file’s SHA-256 fingerprint — for example you published it next to a download — add it as ?expect= plus 64 hexadecimal characters. LightDrawer will warn if the dropped file does not match, and it will not issue a receipt for the wrong file.

Use the fingerprint of the file itself, not the fingerprint from a receipt share link. Receipt links use a different hash (see below).

HTML with an expected fingerprint 
<a class="lightdrawer-stamp" href="https://lightdrawer.org/?expect=YOUR_FILE_SHA256_HERE" rel="noopener">
  Stamp this with LightDrawer
</a>

Optional: hash the file on your page first

If your page already has a file picker, a small helper script can hash the chosen file with the browser’s built-in Web Crypto and then open LightDrawer. The hash is added as #digest=… in the URL fragment. Browsers do not send that fragment to any server, so it does not appear in LightDrawer logs.

The visitor still drops the same file on LightDrawer to confirm it, then completes the human check here. Your page must not call /api/stamp, and you must not put an API key in browser code. API keys are only for a website’s own server — the same pattern Fairview uses.

Host the helper script yourself. Do not load it from lightdrawer.org on every page view; that would make your visitors request a script from us.

HTML 
<label for="file-to-stamp">Choose a file to stamp</label>
<input id="file-to-stamp" type="file">
<a class="lightdrawer-stamp" href="https://lightdrawer.org/"
   data-lightdrawer-file="file-to-stamp"
   data-lightdrawer-status="stamp-status"
   rel="noopener">
  Stamp this with LightDrawer
</a>
<p id="stamp-status"></p>
<script src="lightdrawer-stamp.js" defer></script>

Download lightdrawer-stamp.js and serve it from your own site, next to the page or at whatever path you prefer. The script uses addEventListener only — no inline event handlers — so it works with a strict Content-Security-Policy.

Very large files may use more memory in this helper because it reads the file in one go. For huge videos, use the simple link above instead; LightDrawer itself hashes files in 4 MB chunks.

Check a receipt

If you already have a LightDrawer receipt fingerprint — the long code from the share link, which is the SHA-256 of statement.json, not of the original file — you can link straight to the public lookup page.

HTML 
<a href="https://lightdrawer.org/r/RECEIPT_FINGERPRINT_HERE" rel="noopener">Check this LightDrawer receipt</a>

People can also drop a receipt file on Check a receipt. Do not put a file’s SHA-256 in /r/… or in ?digest= — those addresses look up a receipt fingerprint. A ?digest= link redirects to the lookup page; it is not a file-hash hint. Use ?expect= or #digest= when you mean the original file.

Good to know

What these snippets never do

They never upload the file. They never talk to /api/stamp from your page. They do not add analytics. There is no return= parameter that sends people back to your site automatically — that kind of redirect is easy to abuse. After they download the receipt, they can use the browser’s back button.

Can I open LightDrawer in a new tab?

Yes. Add target="_blank" rel="noopener noreferrer" to the link. The helper script respects target="_blank".
